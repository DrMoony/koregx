# KoRegX v0.2 Pivot — Law & Interpretation Primary Design Spec

> Pivot from drug catalog (deprecated) to **법령 + 행정해석 + 행정규칙 primary**.
> 작성일: 2026-05-09
> 폐기 commit: `4a8d5c4` (P1)
> Maintenance live: `https://koregx.vercel.app` (v0.1 식약처 layer 전체 down)

---

## 1. Pivot 배경

**v0.1 식약처 약물 catalog 폐기 이유**:
- 약물 허가 정보는 commodity (openFDA, IQVIA Pharos, KIMS, drugbank.kr 등 무료/유료 다수 source)
- 사용자(B2B 규제 산업)는 약물 catalog 자체에 돈/시간 안 씀
- 그들이 매일 다루는 진짜 가치 = **"이 법조항이 어떻게 해석됐나"**

**v0.2 USP** (Unique Selling Proposition):
- 한국 헬스케어 법령 본문 + 조문 단위 navigation
- **법제처 행정해석 (expc) 검색** ← Cortellis/IQVIA에 없는 영역
- **식약처 자체 유권해석 corpora** (정보공개·민원회신 누적)
- **행정규칙 (admrul: 식약처·복지부 고시·예규·훈령)**
- **HIRA 약평위·암질심 결정사유** (급여 결정 코퍼스)
- 위 4종을 cross-reference로 chain (조문 → 적용 해석 → 관련 고시 → 결정 사례)

이게 reg professional, 변호사, MA·RA의 daily query에 직결.

## 3. Scope

|---|---|---|
| **Law** | Law, LawArticle | 법제처 OpenAPI `target=law` |

## 4. Architecture

```
Surfaces (3) — 변경 없음
  • Web UI (primary)
  • MCP server (secondary, /api/mcp)
  • REST API (옵션, v0.3+)
       │
       ▼
Application layer (재정의)
  • Search/lookup/chain tools (8-10개)
  • LLM Q&A orchestrator (Gemini 2.5 Flash)
  • Citation verifier (조문/해석 인용 검증)
       │
       ▼
Data access (Prisma) — 변경 없음
  • Postgres (Neon) + pgvector
       │
       ▼
ETL / Source plugin layer (sketch-c, 재사용)
  • SourcePlugin abstract base (M2-1 그대로)
  • Per-source impl: LawGoKr, HiraScrape, MfdsRulings
       │
       ▼
External sources (재정의)
  • 법제처 OpenAPI (OC=mftsky)
  • HIRA scrape (PDF parsing)
  • 식약처 정보공개·민원회신 scrape (HTML)
```

**SourcePlugin 재사용**: M2-1 abstract base의 `fetch → parse → persist` orchestration은 source 종류 무관. 새 source plugin들은 같은 패턴.

## 5. Schema (재정의 — Prisma)

```prisma
// 법령 (대분류)
model Law {
  id              String   @id @default(cuid())
  mst             String   @unique  // 법제처 법령일련번호
  lawId           String              // 법제처 법령ID (그룹)
  nameKor         String              // 법령명한글
  shortName       String?             // 약칭 (약사법 → 약)
  category        String              // 법률 | 대통령령 | 총리령 | 부령
  agencyName      String              // 소관부처명
  agencyCode      String?
  effectiveDate   DateTime?           // 시행일자
  promulgationDate DateTime?          // 공포일자
  promulgationNo  String?             // 공포번호
  amendmentType   String?             // 제정 | 일부개정 | 전부개정 | 타법개정
  scope           String   @default("healthcare")  // healthcare | tagged sub-area
  rawData         Json
  fetchedAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
  articles        LawArticle[]
  interpretations LegalInterpretation[]

  @@index([nameKor])
  @@index([effectiveDate])
}

// 조문 (조·항·호·목)
model LawArticle {
  id              String   @id @default(cuid())
  lawId           String
  law             Law      @relation(fields: [lawId], references: [id], onDelete: Cascade)
  articleNo       String   // "1", "38" 등
  articleSubNo    String?  // "1-2", "38조의2" 등
  title           String?  // 조문제목
  body            String   @db.Text  // 조문내용
  effectiveDate   DateTime?
  changedFlag     Boolean  @default(false)
  rawData         Json?

  @@unique([lawId, articleNo, articleSubNo])
  @@index([lawId])
}

// 행정해석 (법제처 expc) ⭐ USP
model LegalInterpretation {
  id                  String   @id @default(cuid())
  ipNo                String   @unique  // 법령해석례일련번호
  caseNo              String?  // 안건번호
  title               String   // 안건명
  inquirer            String?  // 회신요청자 (예: "강화군")
  respondent          String   // 회신기관명 (보통 "법제처")
  responseDate        DateTime?
  body                String   @db.Text  // 회신문 본문 (HTML/text)
  bodyEmbedding       Unsupported("vector(768)")?  // pgvector
  // 인용된 법령은 Citation 모델에서
  rawData             Json
  fetchedAt           DateTime @default(now())
  updatedAt           DateTime @updatedAt
  Law                 Law?     @relation(fields: [lawId], references: [id])
  lawId               String?  // 주요 인용 법령 (있으면)

  @@index([title])
  @@index([responseDate])
}

// 행정규칙 (admrul: 고시·예규·훈령)
model AdminRule {
  id                String   @id @default(cuid())
  arNo              String   @unique  // 행정규칙일련번호
  name              String   // 행정규칙명
  agencyName        String   // 소관부처
  ruleType          String   // 고시 | 예규 | 훈령
  promulgationDate  DateTime?
  amendmentCode     String?
  body              String?  @db.Text  // 본문 (스크래핑 detail에서 채움)
  bodyEmbedding     Unsupported("vector(768)")?
  rawData           Json
  fetchedAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

  @@index([name])
  @@index([agencyName])
  @@index([promulgationDate])
}

// HIRA 결정 (약평위 + 암질심)
model HiraDecision {
  id              String   @id @default(cuid())
  body            String   // dbc | cancer (약평위 | 암질심)
  meetingDate     DateTime
  meetingNo       Int?     // 제N차
  agendaNo        Int?     // 안건번호
  agenda          String   // 안건명
  drug            String?  // 약물명 (가능한 경우)
  ingredient      String?  // 성분명
  ruling          String   // 통과 | 부결 | 보류 | 기타
  rationale       String?  @db.Text  // 결정사유 (공개분)
  rationaleEmbed  Unsupported("vector(768)")?
  sourceUrl       String   // 원본 PDF URL
  sourceHash      String   // SHA256 of PDF (변경 추적)
  rawData         Json?
  fetchedAt       DateTime @default(now())

  @@unique([sourceHash, agendaNo])
  @@index([body, meetingDate])
  @@index([drug])
  @@index([ingredient])
}

// 식약처 자체 유권해석 / 행정해석 회신
model MfdsRuling {
  id              String   @id @default(cuid())
  externalId      String   @unique  // 식약처 게시 번호
  title           String
  body            String   @db.Text
  bodyEmbedding   Unsupported("vector(768)")?
  category        String?  // 의약품 | 의료기기 | 식품 ...
  responseDate    DateTime?
  sourceUrl       String
  sourceHash      String
  rawData         Json?
  fetchedAt       DateTime @default(now())

  @@index([title])
  @@index([category, responseDate])
}

// Citation: cross-reference (정규식 자동 추출 + manual 보강)
// "약사법 제38조" → Law(약사법) + LawArticle(38) link
model Citation {
  id              String   @id @default(cuid())
  // src
  srcType         String   // interpretation | adminrule | hira | mfds_ruling
  srcId           String
  // ref target
  refType         String   // law | article | adminrule | interpretation
  refId           String
  refLawShortName String?  // matched law's shortName (for display)
  refArticleNo   String?
  // raw text matched
  rawText         String   // "약사법 제38조" 등
  confidence      Float    @default(1.0)  // 정규식 매칭 신뢰도

  @@index([srcType, srcId])
  @@index([refType, refId])
}

// 일반 출처 문서 트래킹 (선택, scraping audit용)
model SourceDocument {
  id          String   @id @default(cuid())
  source      String   // mfds | hira | law-go-kr | mohw
  url         String
  contentHash String
  fetchedAt   DateTime @default(now())
  parsedAt    DateTime?
  parser      String?
  metadata    Json?

  @@unique([source, contentHash])
  @@index([source, fetchedAt])
}
```

## 6. Tool surface (MCP, 재정의)

### Search tools
- `search_law(query, type?)` — 법령명·약칭 검색
- `search_interpretation(query, lawShortName?)` — 행정해석 검색 ⭐
- `search_admin_rule(query, agency?, type?)` — 고시·예규·훈령 검색
- `search_hira_decision(query, body?, dateRange?)` — 약평위·암질심 결정 검색
- `search_mfds_ruling(query, category?)` — 식약처 자체 유권해석 검색

### Lookup tools
- `get_law(id)` — 법령 본문 + 조문 list
- `get_law_article(lawId, articleNo)` — 조문 단일
- `get_interpretation(id)` — 행정해석 본문 + 인용 조문
- `get_admin_rule(id)` — 행정규칙 본문
- `get_hira_decision(id)` — 결정 상세 + 결정사유

### Chain tools (USP)
- `chain_law_lifecycle(lawId, articleNo)` — 조문 + 시행 hx + 적용 행정해석 + 관련 고시
- `chain_interpretation_evolution(lawShortName, articleNo)` — 같은 조문에 대한 해석 timeline
- `chain_natural_query(query)` — 자연어 → LLM이 조문/해석/고시 chain으로 답변 + verify_citations

### Citation verifier
- `verify_citations(text)` — LLM 답변 인용 (예: "약사법 § 38") → DB 매칭 → 존재/내용 검증

## 7. UI structure

```
/                                   KoRegX 랜딩 (재정의 메시징)
/laws                               헬스케어 법령 카드 list (8-12개)
/laws/[lawId]                       법령 상세 + 조문 목차 + 시행 hx
/laws/[lawId]/articles/[no]         조문 단일 + 적용 행정해석 chain + 관련 고시 chain
/interpretations                    행정해석 검색 (ranked by relevance + 최신순)
/interpretations/[id]               회신 본문 + 인용 조문 자동 link
/admin-rules                        행정규칙 검색 (filter by 부처, 종류)
/admin-rules/[id]                   고시·예규·훈령 본문
/decisions                          HIRA 결정 검색 (약평위·암질심 토글)
/decisions/[id]                     결정 상세 + 결정사유
/mfds-rulings                       식약처 자체 유권해석 검색
/mfds-rulings/[id]                  유권해석 본문
/q                                  자연어 query interface (LLM-backed, v0.3)
```

자동 cross-link: 본문 텍스트의 "약사법 제38조" 같은 패턴 → 자동 `<a href="/laws/[lawId]/articles/38">` 변환.

## 8. Acceptance criteria (v0.2 ship)

### User-facing query (5건)
1. **법령 본문**: "약사법 제38조 본문 + 시행 history"
2. **행정해석 검색**: "임상시험 계획 승인 관련 법제처 행정해석 list"
3. **chain query**: "약사법 38조에 대한 행정해석 사례 모두 + 관련 식약처 고시"
4. **HIRA 결정**: "2024년 약평위 통과한 GLP-1 RA 약물 결정사유"
5. **자연어 query**: "임상시험 sponsor의 약사법상 의무가 뭐야?" → LLM이 expc/admrul 인용 답변 + verify_citations

### Deliverable
6. 새 web UI 배포 (`https://koregx.vercel.app` 재배포)
7. MCP server 8-10 tool 작동 (Claude Desktop connector)
8. README + GitHub repo 업데이트 (drug 언급 제거)

## 9. Risks

| Risk | Mitigation |
|---|---|
| HIRA PDF schema 월별 변동 | fixture-driven test + monthly canary |
| 식약처 정보공개 페이지 HTML 변경 | scraper 분기별 검증 + fallback to "manual sync" mode |
| 법제처 OpenAPI rate limit | 서버 캐싱 + redis (Upstash) |
| 행정해석 본문 라이선스 | 법제처 OpenAPI 약관 = 공공정보 무제한 사용. 출처 명시 |
| 자연어 query LLM hallucination | verify_citations 필수 + Gemini 2.5 Flash + cascade |
| Embedding 비용 | text-embedding-004 = $0.025/1M tok. 행정해석 ~100건 × 1000 tok = $0.0025 무시 |
